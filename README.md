# Ad Reporting

Веб-приложение для отчетов по рекламным кампаниям Яндекса.

Пользователь выбирает период, кампании и цели Метрики. Приложение загружает
недостающую статистику из Яндекс.Директа (показы, клики, расходы) и
Яндекс.Метрики (достижения целей), сохраняет ее в PostgreSQL и считает
показатели CTR, CPC, CR, CPA и CPL. Готовый отчет сохраняется как снимок: его
можно открыть позже из истории и выгрузить в PDF или XLSX.

Роли:

- **специалист** – формирует, просматривает и экспортирует отчеты;
- **администратор** – дополнительно управляет пользователями, смотрит журнал
  операций и проверяет доступность API Яндекса.

## Системные требования

Рекомендуемые ресурсы для сервера или рабочей машины:

| Ресурс   | Минимум                 | Рекомендуется |
| -------- | ----------------------- | ------------- |
| CPU      | 2 ядра                  | 2–4 ядра      |
| RAM      | 4 ГБ                    | 6 ГБ          |
| Диск     | 2 ГБ свободного места   | 10 ГБ         |

Больше всего памяти нужно при первой сборке: образ frontend собирается через
`npm ci` и `vite build`. Место на диске уходит в основном на Docker-образы,
объем базы зависит от количества кампаний и длины периодов.

ОС: Linux (x86_64 или arm64), macOS или Windows 10/11 с WSL 2 – везде, где
работает Docker.

Сеть: исходящий HTTPS-доступ к `api.direct.yandex.com` и
`api-metrika.yandex.net`. Также при первой сборке нужен доступ к Docker Hub,
PyPI и npm.

## Требования к ПО

Для запуска через Docker (основной способ):

- Git;
- Docker Engine 24+ (или Docker Desktop);
- Docker Compose v2 (команда `docker compose`).

Python, Node.js и PostgreSQL ставить не нужно – они уже есть в образах:
Python 3.12, Node.js 20 (только для сборки), nginx 1.27, PostgreSQL 16.

Для разработки и запуска без Docker:

- Python 3.12;
- Node.js 20+ и npm;
- PostgreSQL 16.

Доступы Яндекса:

- OAuth-токен с доступом к API Директа и Метрики (`metrika:read`);
- номер счетчика Метрики, к которому у токена есть доступ;
- для агентского аккаунта – логин клиента Директа.

## Установка и запуск

1. Клонируйте репозиторий и перейдите в его папку:

   ```bash
   git clone https://github.com/DariaPash/ad-reporting.git ad-reporting
   cd ad-reporting
   ```

2. Создайте файл настроек из шаблона:

   ```bash
   cp .env.example .env
   ```

   Заполните в `.env` обязательные значения:

   | Переменная                | Назначение                                          |
   | ------------------------- | --------------------------------------------------- |
   | `YANDEX_OAUTH_TOKEN`      | OAuth-токен Яндекса для Директа и Метрики           |
   | `METRIKA_COUNTER_ID`      | номер счетчика Метрики                              |
   | `POSTGRES_PASSWORD`       | пароль базы данных                                  |
   | `INITIAL_ADMIN_USERNAME`  | логин первого администратора                        |
   | `INITIAL_ADMIN_PASSWORD`  | пароль первого администратора                       |

   Необязательные значения:

   | Переменная                                    | Назначение                                          |
   | --------------------------------------------- | --------------------------------------------------- |
   | `YANDEX_DIRECT_TOKEN`, `YANDEX_METRIKA_TOKEN` | отдельные токены, если нужны разные                 |
   | `DIRECT_CLIENT_LOGIN`                         | логин клиента для агентского аккаунта               |
   | `METRIKA_ATTRIBUTION`                         | модель атрибуции Метрики (по умолчанию `automatic`) |
   | `FRONTEND_PORT`                               | порт веб-интерфейса (по умолчанию `3000`)           |
   | `ENABLE_SCHEDULED_SYNC`                       | фоновая синхронизация кампаний и целей              |
   | `SYNC_INTERVAL_MINUTES`                       | интервал синхронизации (по умолчанию 30 минут)      |
   | `LOG_LEVEL`                                   | уровень логирования (по умолчанию `INFO`)           |

3. Соберите образы и запустите контейнеры:

   ```bash
   docker compose up -d --build
   ```

   При первом запуске backend дожидается базы, применяет миграции и создает
   администратора из `.env`.

4. Проверьте, что все три сервиса в статусе `healthy`:

   ```bash
   docker compose ps
   ```

5. Откройте http://localhost:3000 (или порт из `FRONTEND_PORT`). Браузер
   запросит логин и пароль – введите данные администратора из `.env`.
   Других пользователей можно создать в разделе «Пользователи».

Если токен Яндекса не задан или недействителен, интерфейс откроется, но
статистику получить не получится. Проверить доступ к API можно в разделе
«Мониторинг».

### Управление

```bash
docker compose logs -f backend   # логи backend
docker compose up -d --build     # пересобрать после обновления кода
docker compose down              # остановить
docker compose down -v           # остановить и удалить базу данных
```

### Структура проекта

```
backend/
  app/
    api/routes/     HTTP-эндпоинты
    services/       бизнес-логика: импорт, расчет KPI, отчеты, экспорт
    repositories/   доступ к базе данных
    clients/        клиенты API Директа и Метрики
    models/         ORM-модели SQLAlchemy
    schemas/        схемы запросов и ответов (Pydantic)
    core/, db/      ошибки, хеширование паролей, подключение к БД
    scheduler.py    фоновая синхронизация
    bootstrap.py    создание первого администратора
  alembic/          миграции базы данных
  entrypoint.sh     ожидание БД → миграции → администратор → запуск API
frontend/
  src/              страницы, компоненты, хуки, клиент API
  nginx.conf        раздача статики, авторизация, прокси /api
tests/backend/      тесты backend (pytest)
frontend/test/      тесты frontend (vitest)
scripts/            вспомогательные скрипты
```

## Тесты

Backend – тесты запускаются в контейнере на отдельной базе
`ad_reporting_test`, рабочие данные не затрагиваются (нужен заполненный
`.env`):

```bash
./scripts/test-backend.sh
```

Frontend:

```bash
cd frontend
npm ci
npm test
```

## Разработка без Docker

Backend (нужен запущенный PostgreSQL; в `.env` укажите
`POSTGRES_HOST=localhost`):

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cd backend
alembic upgrade head
uvicorn app.main:app --reload
```

Документация API (Swagger) будет доступна по адресу http://localhost:8000/docs.

Запросы `/api` проксируются на
`http://localhost:8000`, адрес можно изменить переменной
`VITE_API_PROXY_TARGET`:

```bash
cd frontend
npm ci
npm run dev
```
